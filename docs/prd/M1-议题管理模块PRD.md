## 一、模块概述

### 1.1 模块定位

**议题 (Issue)** 是 ResearchOS 的核心入口实体。一个议题代表一个待决策的业务问题，是整个"证据 → 洞察 → 推理 → 决策 → 行动 → 回看"闭环的起点。

**一句话描述**：用户提出一个决策问题，系统围绕这个问题收集证据、分析立场、提炼洞察、对抗推理、生成决策建议、跟踪执行。

### 1.2 目标用户

| 角色 | 使用场景 |
|------|---------|
| **管理员 (admin)** | 创建、编辑、删除任何议题，管理团队议题 |
| **分析师 (analyst)** | 创建自己的议题，编辑自己参与的议题，不能删除 |
| **观察者 (viewer)** | 只读浏览所有议题 |

### 1.3 核心用户故事

- **US-1**：作为分析师，我想创建一个新议题来记录需要调研决策的业务问题，以便团队围绕这个问题展开系统化分析
- **US-2**：作为分析师，我想浏览和筛选所有议题，以便快速找到我关注的决策问题
- **US-3**：作为管理员，我想编辑议题的信息和标签，以便保持议题描述的准确性
- **US-4**：作为分析师，我想改变议题的状态，以便推动决策流程前进
- **US-5**：作为管理员，我想删除无效的议题，以便保持工作区整洁
- **US-6**：作为分析师，我想查看议题的详细信息和关联数据概览，以便全面了解决策进展
- **US-7**：作为观察者，我想只读浏览议题列表和详情，以便了解团队的决策动态

## 二、数据模型

### 2.1 Issue 实体字段

```typescript
interface Issue {
  id: string                // UUID，系统自动生成
  tenantId: string          // 租户ID，从当前登录用户的JWT中获取
  title: string             // 议题标题，1-200字符
  description: string       // 背景描述，必填，支持富文本
  domain: IssueDomain       // 领域分类
  status: IssueStatus       // 当前状态
  ownerId: string           // 创建者/负责人 ID
  ownerName: string         // 创建者姓名（冗余存储，避免查询）
  tags: string[]            // 标签数组，自由填写
  decisionDueAt: string     // 决策截止日期 (ISO 8601)
  evidenceCount: number     // 关联证据数（反范式计数，自动维护）
  insightCount: number      // 洞察数（反范式计数，自动维护）
  decisionCardCount: number // 决策卡数（反范式计数，自动维护）
  createdAt: string         // 创建时间
  updatedAt: string         // 最后更新时间
}
```

### 2.2 领域枚举

| 值 | 显示名称 | 说明 |
|---|---------|------|
| `brand` | 品牌 | 品牌定位、形象、认知相关 |
| `product` | 产品 | 产品功能、体验、迭代相关 |
| `market` | 市场 | 市场策略、渠道、投放相关 |
| `strategy` | 战略 | 企业战略、发展方向相关 |
| `operations` | 运营 | 运营效率、流程优化相关 |

        │                       │ │                │ │ │          │
        │                       │ │    ┌───────────┘ │ │          │

**状态流转规则表**：

| 当前状态 | 可转换到 | 触发条件 |
|---------|---------|---------|
| `draft` (草稿) | `collecting` | 用户点击"开始收集" |
| `collecting` (收集证据中) | `analyzing` | 用户点击"开始分析"（建议至少关联1条证据） |
| `collecting` (收集证据中) | `closed` | 用户点击"关闭议题" |
| `analyzing` (分析中) | `pending_decision` | 用户点击"提交决策"（推理完成后） |
| `analyzing` (分析中) | `collecting` | 用户点击"返回收集"（补充证据） |
| `analyzing` (分析中) | `closed` | 用户点击"关闭议题" |
| `pending_decision` (待决策) | `decided` | 用户点击"确认决策" |
| `pending_decision` (待决策) | `analyzing` | 用户点击"返回分析" |
| `decided` (已决策) | `closed` | 用户点击"关闭议题" |
| `closed` (已关闭) | `collecting` | 用户点击"重新激活" |

#### 4.2.2 搜索框

| 属性 | 说明 |
|------|------|
| 类型 | 文本输入框，带搜索图标 |
| 占位符 | "搜索议题标题..." |

**搜索行为**：

| # | 行为 | 详细说明 |
|---|------|---------|
| 1 | 输入文字 | 等待 300ms 无新输入后，调用 `GET /api/issues?search={keyword}&page=1` |
| 2 | 加载中 | 列表区域显示骨架屏/加载动画 |
| 3 | 有结果 | 展示匹配的议题卡片，分页重置到第1页 |
| 4 | 无结果 | 显示空状态插画 + 文字"未找到匹配的议题"+ "清除搜索"按钮 |
| 5 | 清除搜索 | 点击清除搜索后重新加载完整列表 |
| 6 | 联动 | 搜索可与状态标签页、领域筛选叠加使用 |

### 8.3 API 封装

```typescript
// frontend/src/features/issues/api/issues.ts

import { apiClient } from '@/shared/api/client'
import type { Issue, CreateIssueInput, UpdateIssueInput, PaginatedResponse, ApiResponse } from '@research-os/shared'

export const issueApi = {
  /** 获取议题列表 */
  list(params: {
    page?: number
    pageSize?: number
    status?: string
    domain?: string
    search?: string
    sortBy?: string
    sortOrder?: 'asc' | 'desc'
  }): Promise<PaginatedResponse<Issue>> {
    return apiClient.get('/api/issues', { params })
  },

  /** 获取议题详情 */
  getById(id: string): Promise<ApiResponse<Issue>> {
    return apiClient.get(`/api/issues/${id}`)
  },

  /** 创建议题 */
  create(input: CreateIssueInput): Promise<ApiResponse<Issue>> {
    return apiClient.post('/api/issues', input)
  },

  /** 更新议题 */
  update(id: string, input: Partial<UpdateIssueInput>): Promise<ApiResponse<Issue>> {
    return apiClient.patch(`/api/issues/${id}`, input)
  },

  /** 删除议题 */
  delete(id: string): Promise<void> {
    return apiClient.delete(`/api/issues/${id}`)
  },
}
```

| `search` | string | 否 | - | 标题模糊搜索 |

### 9.3 POST /api/issues — 创建议题

**请求体**:

```json
{
  "title": "Q3 NPS下降5分，是否应该降价？",
  "description": "Q3 NPS 从 72 分下降到 67 分，其中价格因素被频繁提及...",
  "domain": "brand",
  "tags": ["NPS", "价格策略"],
  "decisionDueAt": "2026-04-15T00:00:00Z"
}
```

**响应**: 返回创建的议题对象，status 自动设为 `draft`。

### 9.4 PATCH /api/issues/:id — 更新议题

**请求体** (所有字段可选):

```json
{
  "title": "更新后的标题",
  "description": "更新后的描述",
  "domain": "market",
  "tags": ["NPS", "新标签"],
  "decisionDueAt": "2026-05-01T00:00:00Z",
  "status": "collecting"
}
```

**状态流转校验**：后端使用 `canTransition()` 函数校验，不合法返回 400 + `INVALID_TRANSITION`。

### 9.5 DELETE /api/issues/:id — 删除议题

**权限**：仅 `admin`。

**行为**：硬删除议题记录。关联的 `issue_evidence` 记录同时删除（外键级联）。

**成功响应**: HTTP 204 No Content。
