### 2.4 Evidence (证据)

```typescript
interface Evidence {
  id: string
  tenantId: string

  // 来源分类 (仅 2 类)
  sourceCategory: 'internal' | 'external'
  // internal: 内部数据 (问卷、访谈、内部报告、历史数据)
  // external: 外部数据 (第三方报告、公开新闻、竞品分析、社交媒体)

  // 来源类型 (9 种)
  sourceType:
    | 'survey'          // 问卷调研
    | 'interview'       // 访谈记录
    | 'internal_data'   // 内部系统数据 (CRM、BI 等)
    | 'historical'      // 历史数据 / 过往研究
    | 'social'          // 社交媒体数据
    | 'competitor'      // 竞品分析数据
    | 'report'          // 行业报告 / 第三方报告
    | 'news'            // 新闻资讯
    | 'manual'          // 手动录入

  // 来源信息
  sourceLabel: string                  // "2024Q3品牌调研"
  sourceRef: string                    // 原始来源标识，用于去重
  sourceUrl?: string                   // 可选，external 类型可提供原始 URL

  // 内容
  content: string                      // 原始内容
  summary: string                      // AI 生成摘要

  // AI 分析结果 (入库时的初步分析，不依赖议题)
  tags: string[]                       // ["价格", "竞品", "留存"]
  sentiment: 'positive' | 'negative' | 'neutral'   // 情感倾向
  entities: string[]                   // 提取的实体 ["品牌A", "华北区"]

  // 置信度
  confidence: number                   // 0-100，证据本身可信度
  confidenceFactors?: ConfidenceFactors // 可选，置信度因素分解

  // 元数据
  freshnessAt: string                  // 证据时效性时间点 (ISO 8601)
  citation: string                     // 引用格式

  // 时间
  createdAt: string
}
```

> **重要设计决策**：
> - Evidence **没有**全局 `stance` 字段。立场是相对于议题的，在 `IssueEvidence` 中定义。
> - `sourceCategory` 只有 `internal` 和 `external` 两种，**没有** `search`。
> - `sourceType` 不包含 `web_search`。

### 2.5 IssueEvidence (议题-证据关联) ⭐ 核心关联表

```typescript
interface IssueEvidence {
  issueId: string
  evidenceId: string

  // 关联信息
  relationType: 'auto' | 'manual'      // 自动关联 or 手动关联
  relevanceScore: number               // 相关性分数 0-1

  // 立场信息 (相对于该议题)
  stance: 'pro' | 'con' | 'neutral'
  stanceSource: 'ai' | 'manual'        // 立场来源
  stanceConfidence: number             // 立场置信度 0-100
  stanceReason: string                 // 立场判断理由

  // 立场版本控制 (支持重新分析)
  stanceVersion: number                // 整数，每次重新分析 +1
  stanceAnalyzedAt: string             // 最近一次立场分析时间 (ISO 8601)

  // 时间
  createdAt: string
  updatedAt: string
}
```

> **设计理由**：
> - 同一条 Evidence 可以关联到多个 Issue，每个组合有独立的立场判断
> - `stanceVersion` 支持重新分析时跟踪版本，UI 可展示分析历史
> - `stanceAnalyzedAt` 记录最近一次分析时间，用于判断是否需要重新分析

## 三、置信度因素分解

> **注意**：系统中存在两个层级的置信度因素：
> - **Evidence 层**使用简化的 `EvidenceConfidenceFactors`（4 个字段：`sourceReliability`、`dataFreshness`、`sampleSize?`、`methodology?`），定义在 2.4 节 Evidence 接口中。
> - **DecisionCard / Reasoning 层**使用下方的综合 `ConfidenceFactors`（6 个字段），用于决策卡和推理过程的综合评估。

```typescript
interface ConfidenceFactors {
  sourceQuality: number     // 来源可信度 0-100
                            // 权威机构报告 > 内部调研 > 社交媒体
  sampleSize: number        // 样本量充分度 0-100
                            // 大样本 > 小样本 > 单案例
  freshness: number         // 时效性 0-100
                            // 近期数据 > 历史数据
  consistency: number       // 多源一致性 0-100
                            // 多个来源结论一致 > 单一来源
  coverage: number          // 维度覆盖度 0-100
                            // 覆盖多个视角 > 单一视角
  conflictLevel: number     // 冲突程度 0-100 (越低越好)
                            // 无冲突=0, 严重冲突=100
}
```

**综合置信度计算公式**：

```typescript
function calculateConfidence(factors: ConfidenceFactors): number {
  const weights = {
    sourceQuality: 0.25,
    sampleSize: 0.20,
    freshness: 0.15,
    consistency: 0.20,
    coverage: 0.10,
    conflictLevel: 0.10,    // 反向计分
  }

  const score =
    factors.sourceQuality * weights.sourceQuality +
    factors.sampleSize * weights.sampleSize +
    factors.freshness * weights.freshness +
    factors.consistency * weights.consistency +
    factors.coverage * weights.coverage +
    (100 - factors.conflictLevel) * weights.conflictLevel

  return Math.round(Math.min(100, Math.max(0, score)))
}
```

**各因素评分标准**：

| 因素 | 0-25 | 26-50 | 51-75 | 76-100 |
|------|------|-------|-------|--------|
| sourceQuality | 匿名/不可验证 | 社交媒体/非正式 | 内部系统/调研 | 权威机构/专业报告 |
| sampleSize | n < 10 | 10 ≤ n < 100 | 100 ≤ n < 1000 | n ≥ 1000 |
| freshness | > 2年 | 1-2年 | 3-12月 | < 3个月 |
| consistency | 严重矛盾 | 部分矛盾 | 大致一致 | 高度一致 |
| coverage | 单一维度 | 2-3个维度 | 4-5个维度 | 6+个维度 |
| conflictLevel | 无冲突(好) | 轻微冲突 | 中等冲突 | 严重冲突(差) |

> 使用 MySQL 8.0+ 语法，支持 JSON 类型和生成列。

### 4.1 租户与用户

```sql

-- ============================================================
CREATE TABLE tenants (

  name VARCHAR(255) NOT NULL,

-- 用户表

  id CHAR(36) PRIMARY KEY,
  tenant_id CHAR(36) NOT NULL,
```

### 4.3 证据

```sql
-- ============================================================
-- 证据表
-- ============================================================
CREATE TABLE evidence (
  id CHAR(36) PRIMARY KEY,
  tenant_id CHAR(36) NOT NULL,

  -- 来源分类: 仅 internal / external (无 search)
  source_category VARCHAR(16) NOT NULL
    COMMENT 'internal | external',

  -- 来源类型: 9 种
  source_type VARCHAR(32) NOT NULL
    COMMENT 'survey|interview|internal_data|historical|social|competitor|report|news|manual',

  source_label VARCHAR(255),
  source_ref VARCHAR(500),
  source_url VARCHAR(1000)
    COMMENT '可选，external 类型可提供原始 URL',

  -- 内容
  content TEXT NOT NULL,
  summary TEXT,

  -- AI 分析结果
  tags JSON                            COMMENT '标签数组 string[]',
  sentiment VARCHAR(16)                COMMENT 'positive | negative | neutral',
  entities JSON                        COMMENT '实体数组 string[]',

  -- 置信度
  confidence INT DEFAULT 50            COMMENT '0-100',
  confidence_factors JSON              COMMENT '可选, ConfidenceFactors 结构',

  -- 元数据
  freshness_at DATETIME                COMMENT '证据时效性时间点',
  citation VARCHAR(500),

  -- 时间
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,

  INDEX idx_tenant_category (tenant_id, source_category),
  INDEX idx_source_type (source_type),
  INDEX idx_freshness (freshness_at),
  FULLTEXT INDEX ft_content (content, summary),
  FOREIGN KEY (tenant_id) REFERENCES tenants(id) ON DELETE CASCADE
);
```

### 4.4 议题-证据关联

```sql

-- 议题-证据关联表 (含立场 + 版本控制)

CREATE TABLE issue_evidence (
  issue_id CHAR(36) NOT NULL,
  evidence_id CHAR(36) NOT NULL,

  -- 关联信息
  relation_type VARCHAR(16) NOT NULL DEFAULT 'manual'
    COMMENT 'auto | manual',
  relevance_score DECIMAL(3,2) DEFAULT 0.50
    COMMENT '相关性 0.00-1.00',

  -- 立场信息

    COMMENT 'pro | con | neutral',
  stance_source VARCHAR(16) NOT NULL DEFAULT 'ai'
    COMMENT 'ai | manual',
  stance_confidence INT DEFAULT 0
    COMMENT '0-100',
  stance_reason TEXT,

  -- 立场版本控制
  stance_version INT NOT NULL DEFAULT 1
    COMMENT '立场分析版本号，支持重新分析',
  stance_analyzed_at VARCHAR(30)
    COMMENT '最近立场分析时间 ISO 8601',

  -- 时间
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,

  PRIMARY KEY (issue_id, evidence_id),
  INDEX idx_stance (issue_id, stance),
  INDEX idx_stance_version (issue_id, stance_version),
  FOREIGN KEY (issue_id) REFERENCES issues(id) ON DELETE CASCADE,
  FOREIGN KEY (evidence_id) REFERENCES evidence(id) ON DELETE CASCADE
```

## 五、Migration 脚本 (v2 → v3)

```sql
-- ============================================================
-- ResearchOS v2 → v3 迁移脚本
-- 主要变更：
--   1. evidence 新增 sourceCategory 字段 (仅 internal/external)
--   2. evidence 新增 confidence / confidence_factors 字段
--   3. issue_evidence 新增 stance 相关字段 + 版本控制
--   4. issues 移除 search_triggered / searched_at 字段
--   5. evidence 移除 search 相关类型
--   6. reasoning_runs 输入快照移除 searchEvidenceIds
--   7. 新增 data_sources / import_jobs / audit_logs 表
--   8. 移除 issue_insights 关联表（Insight 直接通过 issueId 归属 Issue）
--   9. review_results 表重命名为 reviews，字段全面更新
--       - assessment → outcome, baselineMetric → expectedResult,
--         actualMetric → actualResult, delta → deviation, learnings → lessonsLearned
--       - 新增 tenantId, issueId, tags, generatedEvidenceId, reviewedBy, reviewedAt, updatedAt
-- ============================================================

-- ---------------------
-- Step 1: 备份关键表
-- ---------------------
CREATE TABLE evidence_backup_v2 AS SELECT * FROM evidence;
CREATE TABLE issues_backup_v2 AS SELECT * FROM issues;
CREATE TABLE issue_evidence_backup_v2 AS SELECT * FROM issue_evidence;

-- ---------------------
-- Step 2: evidence 表变更
-- ---------------------

-- 2a. 添加 sourceCategory 字段
ALTER TABLE evidence
  ADD COLUMN source_category VARCHAR(16) NOT NULL DEFAULT 'internal'
    COMMENT 'internal | external'
    AFTER tenant_id;

-- 2b. 添加 source_url 字段 (如果尚不存在)
ALTER TABLE evidence
  ADD COLUMN source_url VARCHAR(1000) AFTER source_ref;

-- 2c. 添加 confidence 和 confidence_factors 字段
ALTER TABLE evidence
  ADD COLUMN confidence INT DEFAULT 50 COMMENT '0-100' AFTER entities,
  ADD COLUMN confidence_factors JSON COMMENT 'ConfidenceFactors' AFTER confidence;

-- 2d. 根据 source_type 自动推断 sourceCategory
UPDATE evidence
SET source_category = CASE
  WHEN source_type IN ('survey', 'interview', 'internal_data', 'historical')
    THEN 'internal'
  WHEN source_type IN ('social', 'competitor', 'report', 'news', 'manual')
    THEN 'external'
  WHEN source_type = 'web_search'
    THEN 'external'    -- 将旧的 web_search 归类为 external
  ELSE 'internal'
END;

-- 2e. 将旧的 web_search 类型迁移为 news
UPDATE evidence
SET source_type = 'news'
WHERE source_type = 'web_search';

-- 2f. 如果旧的 source_category 有 'search' 值，迁移为 'external'
UPDATE evidence
SET source_category = 'external'
WHERE source_category = 'search';

-- 2g. 添加新索引
ALTER TABLE evidence
  ADD INDEX idx_tenant_category (tenant_id, source_category),
  ADD INDEX idx_freshness (freshness_at);

-- ---------------------
-- Step 3: issues 表变更
-- ---------------------

-- 3a. 移除搜索相关字段
ALTER TABLE issues
  DROP COLUMN IF EXISTS search_triggered,
  DROP COLUMN IF EXISTS searched_at;

-- 3b. 添加 decision_due_at 索引
ALTER TABLE issues
  ADD INDEX idx_due_date (decision_due_at);

-- ---------------------
-- Step 4: issue_evidence 表变更
-- ---------------------

-- 4a. 添加 stance 相关字段 (如果尚不存在则添加)
ALTER TABLE issue_evidence
  ADD COLUMN stance VARCHAR(16) NOT NULL DEFAULT 'neutral' AFTER relevance_score,
  ADD COLUMN stance_source VARCHAR(16) NOT NULL DEFAULT 'ai' AFTER stance,
  ADD COLUMN stance_confidence INT DEFAULT 0 AFTER stance_source,
  ADD COLUMN stance_reason TEXT AFTER stance_confidence;

-- 4b. 添加版本控制字段
ALTER TABLE issue_evidence
  ADD COLUMN stance_version INT NOT NULL DEFAULT 1
    COMMENT '立场分析版本号' AFTER stance_reason,
  ADD COLUMN stance_analyzed_at VARCHAR(30)
    COMMENT '分析时间 ISO 8601' AFTER stance_version;

-- 4c. 添加 updated_at 字段
ALTER TABLE issue_evidence
  ADD COLUMN updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
    ON UPDATE CURRENT_TIMESTAMP;

-- 4d. 从旧 evidence.stance 迁移立场数据到 issue_evidence
UPDATE issue_evidence ie
JOIN evidence e ON ie.evidence_id = e.id
SET
  ie.stance = COALESCE(e.stance, 'neutral'),
  ie.stance_source = 'ai',
  ie.stance_confidence = 50,
  ie.stance_reason = '从 v2 evidence.stance 字段迁移',
  ie.stance_version = 1,
  ie.stance_analyzed_at = DATE_FORMAT(NOW(), '%Y-%m-%dT%H:%i:%sZ')
WHERE ie.stance = 'neutral'
  AND e.stance IS NOT NULL
  AND e.stance != '';

-- 4e. 添加索引
ALTER TABLE issue_evidence
  ADD INDEX idx_stance (issue_id, stance),
  ADD INDEX idx_stance_version (issue_id, stance_version);

-- ---------------------
-- Step 5: 移除 evidence 表旧的 stance 字段
-- ---------------------
-- 注意：为安全起见，建议确认数据迁移完成后再执行
-- ALTER TABLE evidence DROP COLUMN IF EXISTS stance;

-- ---------------------
```
